把需求和流程交代清楚 ​

这一部分只解决一个问题：怎样把自己脑中的做法，准确地说成智能体可以执行的流程。

“帮我整理一下”“把后续安排好”这类说法，人类同事可能会结合经验猜出你的意思，智能体却容易漏步骤、用错资料或做出与你预期不同的动作。关键不是把话写得更长，而是使用含义明确的操作表达，把每一步说清楚。

把任务变成可执行的流程 ​

要让智能体做对事，先像交代一位同事一样，把目标、对象、动作和完成方式讲明白。下面三步合在一起，就是一条可执行的任务描述。

用准确动词描述动作 ​

准确表达不是堆砌黑话，而是选用能够对应具体操作的动词：

想表达什么推荐使用的动词说明
找到信息读取、检索、筛选说明从哪里取得哪些资料
整理信息提取、分类、去重、汇总说明怎样处理原始内容
检查信息核对、比对、验证说明依据什么检查
形成结果生成、写入、创建、发送说明产生什么或改变什么
交回结果返回、列出、标记说明智能体完成后要提供什么证据

例如，不说“看看会议里都说了什么”，而说“读取本次会议纪要，提取行动项”。不说“把时间弄一下”，而说“查询团队日历，比对行动项是否存在时间冲突”。

为动作补齐对象和字段 ​

只有动词还不够。每一步最好说清楚三个部分：

动作 + 操作对象 + 需要处理的字段或规则

例如：

  • 读取 + 本次会议纪要与工作群最新消息
  • 提取 + 行动项 + 事项、负责人、截止时间和出处
  • 比对 + 行动项与团队日历 + 检查时间冲突
  • 创建 + 任务与日程 + 使用确认后的负责人和时间

这样，智能体不仅知道“要整理会议”，还知道从哪里读取、要提取什么，以及下一步操作哪些对象。

用顺序和条件串成流程 ​

最后，用流程词把各个动作连接起来：

  • 先、再、随后、最后：说明执行顺序。
  • 若……则……，否则……：说明分支条件。
  • 确认后、通过后：说明什么时候可以继续执行。
  • 直到……为止：说明流程的结束条件。

例如，把“把工作讨论会后续安排好”改写为：

先读取本次会议纪要和工作群最新消息，提取行动项的事项、负责人、截止时间和出处；再查询团队日历，比对是否存在时间冲突。若负责人或截止时间缺失，则标记为待确认，不自行补写；信息完整后生成任务、日程和通知草稿，待我确认后创建并发送，最后返回任务链接、日程状态和消息发送结果。

动手改写把口语化要求换成可执行表达
0/4

依次点击四句话，观察模糊要求怎样变成可执行流程。

判断流程有没有说清楚，可以逐步问：做什么动作？操作什么对象？处理哪些字段？先后顺序是什么？遇到不同情况怎么办？完成后返回什么？

多用行业术语与业务口径 ​

清楚的执行流程是基础。如果希望智能体的判断和表达更贴近真实业务，还要补充当前行业的专业术语，以及你所在组织采用的具体口径。

不要只丢给它几个行业词汇，而要同时提供：

  • 术语名称与定义：这个词在当前行业中具体指什么。
  • 企业内部口径：公司怎样计算、分类或使用这个术语。
  • 正确示例：一段符合要求的历史材料或标准结果。

例如在活动运营场景中，可以说明“报名人数、到场人数、核销人数、到场率”的定义和计算方式，再要求智能体据此整理活动复盘。这样它不会只写“现场参与情况较好”，而能按照统一口径计算并呈现业务数据。

行业术语不能代替清楚的执行流程。先让智能体知道怎样做，再让它按照你的业务口径做得更准确。

通过多轮沟通把流程调顺 ​

不需要在第一句话里把所有细节都说对。把智能体当作协作同事：先交代你已经明确的目标和资料，再根据它给出的结果补充反馈，一起把流程调顺。

当第一次结果不符合预期时，不必从头重写整段要求。直接指出具体问题，并告诉它下一轮怎样调整：

  • 遗漏了什么：例如“漏掉了会议纪要里的负责人和截止时间，请补齐后再生成任务草稿。”
  • 哪一步不对：例如“先不要创建日程，先把有时间冲突的事项单独列出来让我确认。”
  • 结果该怎样改：例如“把任务按负责人分组，并在每项后保留原始出处。”

每一次反馈都会成为下一轮对话的上下文。经过几轮“给结果 → 看问题 → 补反馈”，就能把一项模糊的想法逐步收敛成稳定、顺畅的执行流程。

关键不是一次性写出完美指令，而是让每一轮反馈都足够具体，能让下一步比上一步更接近你要的结果。
