明确交付要求与质量标准 ​

“生成了一段漂亮总结”不等于任务完成。交任务时就要说清交付形式和评估标准；收到结果后，再据此决定是继续沟通迭代，还是结束任务。

定义产出物格式与要求 ​

同一份内容，做成聊天里的文字、可编辑的 Word，还是可导入系统的 JSON，交付标准完全不同。先说清楚“要交什么”，智能体才知道该以什么方式组织内容、调用工具和返回结果。

至少明确四件事：

  • 内容媒介：文本、图片、视频、表格、演示文稿，还是其他类型的内容。
  • 文件或数据格式：如 Markdown、Word、Excel、PPT、PDF、CSV、JSON、CAD 源文件等。
  • 交付方式：直接在对话中展示、生成可下载文件、写入指定文件夹，还是导入业务系统。
  • 可编辑与结构要求：是否需要保留源文件、工作表、公式、图层、字段结构或 JSON schema。

例如，不要只说“做一份复盘”，而要说“生成一份可编辑的 Word 复盘报告，并同时输出一张用于汇报的 PNG 数据图；数据明细另存为 Excel，保留原始字段和计算公式。”如果是给系统对接，则应明确“返回符合接口字段定义的 JSON，不要用自然语言替代结构化数据”。

制定专业的评估标准 ​

评估标准不能只写“做好一点”或“专业一些”，而要与具体的交付物和使用场景对应。把标准写成可检查的条目，智能体才能据此自检，你也能快速判断结果是否可用。

可以从以下四类标准中选择适用项：

  • 规范是否符合：文件格式、版式、命名、尺寸、页数、字段或接口 schema 是否满足要求。
  • 内容是否专业：是否使用正确的行业术语、业务口径、数据来源与表达方式。
  • 质量是否达标：信息是否准确、完整、无矛盾；论证、计算、图表或设计是否达到预期水平。
  • 是否便于使用：能否直接阅读、编辑、导入、演示或交给下一位同事继续使用。

例如，要求生成 Excel 时，标准可以是“保留原始字段、公式可编辑、汇总表与明细表能对应”；要求返回 JSON 时，标准可以是“字段完整、类型正确、能通过既定 schema 校验”；要求生成 PPT 时，则应明确页数、受众、叙事结构和视觉规范。

根据评估结果决定：继续迭代，还是结束任务 ​

评估不是为了挑错，而是为了给下一步一个明确结论。每次检查后，都应落到以下三种处理之一：

  • 达标，结束任务：所有必选标准通过，产出物可以直接交付或使用。
  • 有明确差距，继续迭代：把未通过的具体条目、参考示例和修改方向反馈给智能体，再让它基于同一份材料修订。
  • 缺少判断依据，先补充信息：补充资料、业务口径或示例后再评估；不要在标准不清或资料不足时强行给出“完成”。

反馈应尽量具体，例如“第 3 页的结论没有对应数据来源，请补上出处并按销售团队汇报模板重写”，而不是只说“再专业一点”。这样多轮沟通会持续收敛到同一套质量标准。

先把专业标准讲清楚，再按标准检查和反馈；达到标准就结束，未达到就继续协作。
